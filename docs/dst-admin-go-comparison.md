上游采用 GPLv3，本项目采用 MIT。本批借鉴产品功能与交互需求，代码在本项目中独立实现，没有引入、复制或修改上游源文件，也没有新增第三方依赖。

## 新功能的使用与边界

### 玩家准入名单

进入「房间 → 编辑 → 玩家准入名单」，切换黑名单/白名单，输入 `KU_` 开头的 Klei ID。ID 支持字母、数字、短横线和下划线。输入规范化、大小写去重和读改写互斥在后端执行。

- 黑名单写入 `blocklist.txt`；白名单写入 `whitelist.txt`。不操作其它房间的文件。
- 白名单用于预留位置，不等于“仅允许白名单进入”。沿用本项目按名单人数预留的位置策略，过滤注释、空行、无效 ID 和重复项，并限制为不超过房间最大人数。预留位包含在最大人数内。
- 修改白名单后，只刷新 `cluster.ini`，不重写世界定义、模组配置或存档。若配置刷新失败，接口明确说明名单已经保存，可安全重试。
- 修改需要下次重启房间生效。添加黑名单不会立即踢人；需要立即封禁在线玩家时，仍使用玩家列表中的封禁操作。
- 名单绑定当前编辑的房间，不跟随顶部房间选择器改变。管理员原接口保持兼容，并补上并发追加的保护。

接口为 `/api/player-lists?room=<ID>&kind=blocklist|whitelist`：GET 查询；POST 添加；DELETE 移除。写入请求体为 `{"kleiId":"KU_example-1"}`。缺少房间、未知名单类型和额外请求字段会被拒绝。

### 快捷操作

「概览 → 快捷操作」提供：

- **立即保存**：并行请求所有仍运行的启用分片，等待 `ShardGameIndex:SaveCurrent` 的写入完成回调。分别报告成功、未运行而跳过的分片及失败原因；不把部分成功描述为全部成功。
- **全服公告**：主分片执行游戏原生 `c_announce`。最多 500 个字符，禁止换行和控制字符；中文、表情、引号和反斜线作为文本编码。等待游戏回执后才报告提交完成，不将其等同于每位玩家已经看到消息。
- **主世界快进一天**：明确确认后，在主分片调用 `c_skip(1)`。它会改变主世界的时间和实体状态，不是保存或回档。与回档共用一分钟冷却；超时不会自动重试。游戏明确拒绝“世界未就绪”时允许重新操作。

新操作只接受 `POST /api/quick-action?room=<ID>`，请求体为 `{"action":"save"}`、`{"action":"announce","message":"欢迎"}` 或 `{"action":"skipday"}`。必须明确指定房间，不接受任意 Lua 或额外字段。沿用登录鉴权和自动维护互斥。

游戏命令依据：[游戏控制台函数](https://github.com/taichunmin/dont-starve-together-game-scripts/blob/master/consolecommands.lua)。本批没有添加永久删除全部世界的重置快捷按钮。

### 聊天与进出记录

从侧边栏「玩家日志」进入。参照上游的[玩家日志截图](https://github.com/carrot-hu23/dst-admin-go/blob/main/docs/image/playerlog.png)及[前端交互](https://github.com/carrot-hu23/dst-manage-web2/blob/main/src/pages/PlayerLog/index.jsx)，在本项目中独立实现筛选工具栏、事件标签表格、分页、ID 复制及黑名单操作；概览仅保留运行日志。

本次实际克隆并核对相同提交的 [`internal/collect/collect.go`](https://github.com/carrot-hu23/dst-admin-go/blob/d189b9e215f073de2973242f72aacc3bd8747016/internal/collect/collect.go)，独立实现对应采集链路：

- 后台每 5 秒读取全部已定义分片的 `server_log.txt` 与 `server_chat_log.txt`，不依赖日志页是否打开。首次读取补采现有文件；面板退出前进行最后一次采集。
- 从认证行提取完整昵称和 Klei ID，以连接 GUID 关联 IP、Steam ID，以明确的玩家 ID/实体归属及角色生成日志关联角色。保留角色和地址变化，避免把后来的角色或重连地址写到较早事件上。
- 进入、离开、聊天、私聊、死亡、复活、公告均保存为历史。昵称关联使用同一次游戏启动内的精确匹配，同名多个账号时保留未知 ID，不以模糊昵称关联封禁目标。原始聊天明确给出的 ID 不受同名影响。
- 从游戏 `Current time` 启动时间及运行时长还原事件时间；缺少启动时间时仅显示运行时长，不把采集日期冒充事件日期。历史排序沿用采集文件顺序，游戏重启后计时归零也不重排旧记录。
- 历史和两个源文件的完整行游标、首尾指纹一同原子保存于 `<存档根目录>/playerlogs/<Cluster>/<Shard>.json`，目录 0700、文件 0600（Windows 依文件系统权限规则）。日志追加、截断或替换后继续采集；面板重启不重复导入，删除的历史不会从同一段原始日志再次出现。游戏自己的日志、存档和名单文件不被采集器修改。
- 分页与搜索覆盖已归档历史，不再限制于最近 200 条。可按分片和事件筛选，搜索昵称、Klei ID、Steam ID、IP、角色或内容；每页 10 / 20 / 50 / 100 条，切换筛选返回第一页。页面自动刷新可暂停，离开页面停止页面轮询，后台采集继续运行。
- 可复制 Klei/Steam ID、访问有效 Steam 主页、确认加入黑名单或删除单条/选中历史。加入黑名单仍需重启房间生效；历史删除仅删面板副本，不删除原始游戏日志。删除与选择绑定房间、分片、页码和筛选上下文。
- 不执行日志中的 Lua 或 HTML；沿用鉴权，拒绝越界目录、日志文件链接及非普通文件。历史文件损坏时明确报错并保留原文件，不覆盖为空历史。

查询接口：`GET /api/chat-log?room=<ID>&shard=<name>&kind=all&search=<text>&page=1&limit=10`，返回 `entries/total/page/pageSize`；省略 `page` 的旧调用仍返回最近 `limit` 条。`limit` 为 1–500，搜索最多 200 个字符。

删除接口：`DELETE /api/chat-log?room=<ID>&shard=<name>`，JSON 请求体 `{"ids":[1,2]}`。只接受明确房间和分片、1–500 个正整数记录 ID；返回实际删除数。

未引入上游 SQLite/GORM 或复制 GPL 源码。历史随时间增长，可在页面删除不再需要的记录；在首次采集前已被游戏覆盖的日志不在补采范围内。

### 容器内存

Linux 检测到可读的有限 cgroup 内存配额时，概览额外显示「容器内存配额」。宿主机内存卡片继续展示整机数据。

支持 cgroup v2、v1 memory 控制器、命名空间根目录、子树挂载和可见父级约束。可用量取各层配额剩余量的最小值，同级进程占用父级配额时也会限制当前容器；v1 父级只有在层级记账开启时才计入。用量包含内核计入 cgroup 的缓存，不能把配额剩余量当作独占物理内存。

可用量不超过 10% 时提醒。超过限额时显示真实的零剩余；配额已知而用量读取失败时报告错误，不伪造零值。未检测到配额时不添加卡片。Windows 保持原来的系统内存采样。

## 仍可考虑的后续项

上游还具有大厅查询、玩家长期活跃/死亡/角色统计和地图预览。这些不是本批已实现功能：大厅查询涉及外部接口与凭据；长期统计需要设计记录保留与清理；地图预览需要独立适配存档格式。

动态 `modinfo.lua` 沙箱仍按原路线图单独评估，避免为少量动态配置引入无资源限制的 Lua 执行。

## 验证

新增覆盖包括名单并发修改、路径和请求参数校验、保存的部分失败、游戏回执关联、超时与冷却、Lua 5.1 中文和注入文本执行、日志边界/追加/替换，以及 cgroup 层级限额。前端浏览器测试使用拦截 API 的独立 fixture，覆盖确认、房间切换竞态、搜索、轮询停止、HTML 转义及手机深色布局，不写入真实游戏数据。

完整前端回归已将 `check-panel-tools-browser.mjs` 加入 `npm test`。玩家历史新增覆盖身份回填、重名冲突、并发连接 GUID、角色变更、进出/死亡/复活、持久化重启、日志轮转、删除隔离及后台采集；本地真实游戏日志可用临时历史目录作只读关联验证，不启动或停止实际游戏。
