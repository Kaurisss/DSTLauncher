# 完整迁移与存档地图预览

## 完整迁移

入口：**备份 → 完整迁移**。导出和导入前停止全部房间；上传与校验可以在服务器运行时进行。

迁移包包含全部房间定义、各分片存档及配置（含停用分片）、玩家名单、配置方案和自动维护计划。游戏服务器程序、模组实体、面板登录配置及 Webhook 设置不包含在包中。游戏令牌和房间密码会保留。

1. 在原面板选择“导出全部房间”，生成后点击“下载迁移包”。浏览器直接下载 ZIP，无需将整个文件读入网页内存。
2. 在目标面板选择“上传迁移包”。后台校验版本、文件清单、文件大小、ZIP CRC 和 SHA-256，完成后显示房间、分片、配置方案、文件数量及总大小。
3. 点击“导入为新房间”并确认。房间 ID、所有分片端口与集群通信密钥重新分配，主世界地址设置为本机。已有房间保留。游戏令牌和房间密码恢复到新房间。
4. 检查新房间设置，安装游戏服务器并下载所需模组，然后启动。

“应用迁移包中的自动维护计划”默认不勾选。勾选后会替换目标面板的全局自动维护计划；配置方案始终以新的方案 ID 保存。

导出和应用期间，其他更改操作及自动维护被互斥锁隔离，同时暂停崩溃自动重启。导入先准备全部新目录，再一次性写入房间定义；准备或持久化失败时，清理本次新目录和新方案。面板关闭时取消迁移并清理临时文件。

临时包位于 `<存档根目录>/migration-tmp/`，在当前面板进程中可保留最多 4 个任务；可用“清除临时包”移除当前任务。创建新任务时清理已超过 24 小时的任务，关闭面板时清理当前进程的任务。网页关闭对话框后，可重新打开继续查看；同一浏览器标签页刷新后会恢复任务查询。

格式版本为 `dstlauncher-migration` / `1`：

```text
manifest.json
rooms/<原房间 ID>/cluster.ini
rooms/<原房间 ID>/<分片>/...
profiles/<原方案 ID>.json
```

ZIP 最大 8 GiB，清单最大 32 MiB，解压后总载荷最大 32 GiB，最多 100000 个文件。越界路径、Windows 保留名、重复或大小写冲突项、链接、未知载荷和缺失文件均拒绝导入。

接口沿用面板鉴权：

| 接口 | 用途 |
| --- | --- |
| `POST /api/migration/export` | 创建导出任务，返回 `id` |
| `POST /api/migration/upload` | 请求体直接发送 ZIP 文件，创建校验任务，返回 `id` |
| `GET /api/migration/job?id=...` | 任务类型、状态、进度、预览、错误和导入后的房间 ID |
| `POST /api/migration/apply` | `{"id":"...","applyPlan":false}`，确认应用已校验的包 |
| `GET /api/migration/download?id=...` | 下载已完成的导出包 |
| `DELETE /api/migration/job?id=...` | 清理已完成或失败任务 |

任务状态：`working`、`ready`、`failed`；任务类型：`export`、`upload`、`import`。预览及轮询结果不返回游戏令牌和房间密码。

## 存档地图预览

入口：**存档 → 地图预览**。使用自定义 Select 选择房间和分片，支持停用分片。底图直接使用存档中的逐格地形，显示实际陆地、海洋、岛屿、道路和地形边界。猪王、虫洞、洞穴出入口、试金石、远古地标和传送门用不同图标显示；重要地标默认显示名称，放大后显示更多名称并避让重叠。

支持 100%–800% 缩放、滚轮缩放、鼠标/触摸拖动平移。聚焦地图后用方向键平移，Home 键复位。右侧列表可搜索地标，点击后地图定位并高亮；虫洞按存档真实记录引用配对，选中一端时显示连线。地形图例按实际地块名称着色，海难模组地形使用存档映射 ID，不写死数字。没有已知配色的模组地形以“未识别地形”及内部名列入图例。

地形配色与逐格位图绘制移植自 MIT 项目 [DMP Web](https://github.com/miracleEverywhere/dst-management-platform-web/blob/161908b3acb531b5e9639a43b7be17ba6fbd307e/src/views/tools/world-map/worldMap.js)，保留署名与完整许可，见 [第三方声明](../THIRD_PARTY_NOTICES.md)。当前使用地形色板和矢量地标图标；未引入游戏纹理提取工具链。

面板只检查 `save/session/<session>/` 下直接存在的数字世界文件，按修改时间选择最近保存点；同一 session 时间相同时比较数字保存点编号。不会递归进入玩家目录。支持明文、`KLEI     1 ` 明文头与 `KLEI     1D` 的 Base64/LE32/zlib 封装。兼容直接返回数据表及游戏实际使用的 `savedata` / `tablefunctions` 序列化包装；仅提取地图与地标对应的字面量返回表，不调用函数或执行 Lua。

单个快照及解压文本均限制为 32 MiB，最多 750000 个静态表项、4194304 个地块和 2000 个已识别地标。`map.tiles` 必须具有已验证的 9 字节 VRSN 版本头，其后为精确 `width*height` 个 LE16 地块 ID；按当前存档的 `world_tile_map` 查找地形名。未知版本、损坏的长度和缺失的地形映射明确报错。

`GET /api/map?room=<ID>&shard=<分片名>` 返回尺寸、保存时间、保存点编号、地块及地形名称表和地标，不返回原始存档或玩家数据。地块载荷为 `terrain.tiles`（原始行序的 LE16 / Base64，无 VRSN 头），`terrain.specs` 为 `{id,name}` 列表。原始格式调查见 [DST 世界快照地图格式调查](dst-map-format.md)，代码移植依据见 [源码复用调查](dst-map-reuse-research.md)。

已使用构造的明文/压缩夹具和项目现有的真实森林、洞穴、海难快照验证。三个世界分别解码出 160000、180625、291600 个地块，全部命中存档自己的地形表，包含大于 255 的模组地块 ID。另核对猪王落在木地板、传送门落在草地、远古祭坛落在砖地、档案馆落在档案馆地形，验证图像行序与地标坐标一致。火山暂无保存点。兼容性验证只读世界文件，没有修改原存档。
