# 配置方案、故障诊断与事件通知

## 配置方案

房间页工具栏 → 配置方案。选择已停止的源房间，填写名称并保存；也可直接点击“复制房间”。从方案创建后会进入新房间编辑页，可填写令牌及房间密码，再开服。

方案包含房间设置和每个分片的 `worldgenoverride.lua`、`leveldataoverride.lua`、`modoverrides.lua`，保留停用分片的配置。新房间会重新分配 ID、端口和集群密钥。方案不包含游戏存档、玩家名单、服务器令牌、房间密码和宿主机的面板设置；主世界地址重置为本机。

方案支持 JSON 导入、导出、删除，文件上限 8 MiB，保存于 `<数据根目录>/dst_save/profiles/`。导入只接受上述配置文件和能静态解析的 Lua 数据；动态代码或未知文件会报错。更改方案或删除方案不影响已经创建的房间。

接口：

- `GET /api/profiles` 列出方案摘要；`GET /api/profiles?id=<ID>` 下载方案 JSON。
- `POST /api/profiles`：`{"room":1,"name":"朋友联机"}`。
- `POST /api/profiles/import`：直接提交导出的 JSON 对象。
- `POST /api/profiles/apply`：`{"id":"<ID>","name":"新房间"}`。
- `POST /api/rooms/copy`：`{"room":1,"name":"房间副本"}`。
- `DELETE /api/profiles?id=<ID>` 删除方案。

## 故障诊断

概览 → 分片管理 → 故障诊断。检查令牌是否缺失、最近一次进程创建失败、各分片最近 400 行日志和共享模组更新输出。覆盖身份验证、端口绑定、模组下载、Lua 错误、内存不足、子世界连接主世界失败及版本不匹配。

每条结果显示错误阶段、原始依据和下一步建议。只有错误行或脚本堆栈中明确出现的工坊 ID 才会关联模组名称与工坊链接。近期日志可能保留之前启动的问题；成功启动会清除该分片此前的“进程创建失败”记录。共享模组下载区显示安装级记录，适用于所有房间。

接口：`GET /api/diagnostics?room=<ID>`。返回检查时间、配置检查、各分片结果、共享下载结果。已配置的房间令牌、密码和集群密钥会从日志依据中隐藏。界面以文本显示原始日志。

## 事件通知

设置 → 事件通知。填写 Webhook 地址，选择通知事件和房间，保存后可测试发送。默认关闭。测试使用已保存配置，即使通知尚未启用也可测试。

支持事件：

| 事件 | 触发条件 |
| --- | --- |
| `crash_limit` | 连续崩溃达到自动重启上限 |
| `maintenance_failed` | 自动重启或更新维护失败 |
| `backup_failed` | 手动或自动备份失败 |
| `update_failed` | 共享模组下载/更新失败，手动中止除外 |
| `start_failed` | 分片进程创建失败 |
| `started` | 分片启动就绪 |
| `stopped` | 分片停止 |

房间列表留空表示全部房间；指定房间后只筛选带房间 ID 的事件。自动维护及共享模组更新属于全局事件，也会发送。签名密钥留空保存时保留已有密钥，可勾选“清除已保存密钥”移除。

接收端需接受 HTTP POST JSON，2xx 代表送达。示例：

```json
{
  "id": "事件唯一标识",
  "time": "2026-11-07T10:00:00Z",
  "event": "crash_limit",
  "roomId": 1,
  "roomName": "朋友联机",
  "shard": "Master",
  "message": "连续崩溃已达到自动重启上限，请检查日志",
  "version": "v0.1.2"
}
```

全局事件不携带 `roomId`、`roomName` 和 `shard`。请求头包含 `X-DST-Timestamp`（Unix 秒）。设置密钥后额外发送：

```text
X-DST-Signature: sha256=<HMAC-SHA256(secret, timestamp + "." + 原始请求体) 的十六进制结果>
```

通知是通用事件 JSON，需要接收端或适配服务转换为企业微信、飞书等机器人的消息格式。请求最长等待 8 秒，不跟随重定向。后台最多缓存 64 个待发送事件，单次发送，不自动重试；队列满和非 2xx 均显示失败原因。最近 20 次结果保存在当前面板进程内，重启后清空。关闭面板会取消尚未完成的发送。

配置及签名密钥保存在 `<数据根目录>/dst_save/notifications.json`，创建为仅当前用户可读写的文件（Windows 由文件系统 ACL 管理）。API 查询仅返回是否已保存密钥，不返回密钥内容。所有接口沿用面板鉴权。

接口：`GET/PUT /api/notifications`、`POST /api/notifications/test`。保存字段为 `enabled`、`url`、`events`、`rooms`，可选 `secret`：省略表示保留，空字符串表示清除。测试失败会返回可读取的错误，并保留最近投递结果。
