# 异地备份与恢复检查

## 异地备份

入口：**系统设置 → 自动维护与异地备份**（也可从「备份与回档」页工具栏的「异地备份设置」快捷跳转）。默认关闭，启用后新创建的手动和自动备份都会进入后台同步队列。

支持两种目标：

- **目录 / NAS**：填写面板所在机器可访问的绝对路径或 Windows UNC 路径，例如 `D:\Backups`、`\\NAS\Backups` 或 Linux 的 NAS 挂载目录。目标不能与面板存档根目录互相包含。
- **WebDAV**：填写已存在的 HTTP/HTTPS 目录地址，按需填写用户名和密码/应用密码。面板通过 MKCOL、PUT、MOVE、PROPFIND 和 DELETE 操作自己的备份目录，不跟随重定向。保存密码后查询只返回 `passwordSet`；留空保存表示保留，勾选清除才移除。

点击“测试已保存的备份目标”会写入并删除一个小测试文件。测试使用已经保存的设置；WebDAV 测试最长 30 秒。

每个面板使用独立随机目录：

```text
<目标>/dstlauncher-<面板标识>/Cluster_<ID>/<备份名>.zip
```

文件先写入临时名称，完成后再改为正式备份名。同步成功后保留本次副本，再按备份时间保留其余最近副本，合计不超过设置的份数（每个房间 1–100 份）。手动重试较老备份时，本次同步的副本同样会保留。只清理本面板独立目录下、符合面板生成命名规则的备份，不改动其他文件、本地备份或其他面板的目录。

备份页显示最近同步状态，可点击“同步”或“重试同步”。同步失败不会把本地备份结果改为失败，错误会明确指出异地阶段失败，并触发现有 `backup_failed` Webhook 事件。需要在事件通知中启用该事件和相应房间。

后台串行执行，最多保留 40 个待同步任务，每个任务最长 30 分钟。修改目标只影响之后入队的任务；已排队任务沿用入队时的目标。超过上限会返回队列已满。关闭面板会取消未完成同步并关闭文件句柄，本地备份保留，可重启后手动重试。当前进程保留最近 40 项同步记录，重启后列表清空；“无同步记录”表示没有本次进程中的记录。待同步任务只保存在内存中，重启会丢失。

配置和面板标识保存在 `<存档根>/backup-remote.json`，文件创建权限为 `0600`（Windows 由文件系统 ACL 管理）。该设置不包含在完整迁移包中。

## 恢复检查

入口：**备份 → 对应备份的“回滚”**。

检查在私有临时目录中进行，房间可以继续运行：

1. 逐项读取 ZIP，验证 CRC、文件大小、路径、重复项、大小写冲突及特殊文件。
2. 计算整个 ZIP 的 SHA-256，检查 `cluster.ini` 与世界保存点是否存在。
3. 列出当前房间全部分片（含停用分片）以及备份中实际存在的分片，统计数字世界保存点和玩家保存目录/文件，读取保存点元数据中的天数、季节及时间。
4. 提示缺失世界、玩家目录或元数据读取错误。元数据有保存点而世界文件缺失时禁止恢复；没有任何世界保存点或缺少 `cluster.ini` 也禁止恢复。
5. 从备份的临时内容读取地图，复用已有地形预览。地图预览不可用时会显示具体原因，ZIP 检查结果仍保持可见。

“玩家保存目录”按备份中的 session/玩家子目录计数，同一玩家跨 session 可能对应多个目录。旧版备份未记录原文件修改时间时，保存时间显示为空；天数/季节仍从 `.meta` 内容读取。新生成的备份保留原文件时间。

确认恢复前需停止目标房间。恢复任务会再次计算源 ZIP 摘要，与刚检查的内容一致才替换；备份在检查后发生变化时必须重新检查。使用当前房间设置、令牌与端口生成本机配置，世界、模组与玩家存档从备份恢复。

恢复前的完整目录保留为：

```text
Cluster_<ID>.before-restore-<时间>-<随机标识>
```

新目录替换失败会把原目录移回；损坏包在替换前就被拒绝。界面恢复完成后显示旧目录位置。保留的旧目录不自动删除。

关闭检查对话框可取消正在执行的检查；恢复期间禁止关闭。检查最多保留 3 个临时任务，新检查会淘汰最旧的已完成任务，并清理本进程中超过一小时的任务。面板正常关闭时清理本进程的检查目录。

上限：ZIP 8 GiB、解压载荷 32 GiB、100000 个条目。临时文件位于 `<存档根>/backup-checks/`。

## 接口

均沿用面板鉴权。

| 接口 | 请求/用途 |
| --- | --- |
| `GET /api/backup-remote` | 目标设置（不含密码）及最近同步记录 |
| `PUT /api/backup-remote` | `enabled,kind,directory,url,username,keep`，可选 `password` |
| `POST /api/backup-remote/test` | 测试已保存目标的写入/删除权限 |
| `POST /api/backup-remote/sync?room=<ID>` | `{"name":"<备份名>.zip"}`，重试已有备份 |
| `POST /api/backups/check?room=<ID>` | `{"name":"<备份名>.zip"}`，返回检查任务 ID |
| `GET /api/backups/check?id=<ID>` | 检查/恢复状态、进度、摘要和分片报告 |
| `GET /api/backups/check/map?id=<ID>&shard=<名称>` | 已检查内容中的地图 |
| `DELETE /api/backups/check?id=<ID>` | 取消检查或清理已完成任务 |
| `POST /api/backups/restore?room=<ID>` | `{"id":"<检查 ID>","sha256":"<摘要>"}`，返回任务 ID，继续查询状态 |

检查状态：`checking`、`ready`、`restoring`、`restored`、`failed`。旧 GET 恢复接口保留兼容，但也先完整检查和解压，再替换目录。
