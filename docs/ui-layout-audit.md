# 前端页面布局与功能入口审查报告

本文档基于当前前端源码（`web/src/`），系统梳理 DSTWin 管理面板在**信息架构、功能入口归属、交互可发现性以及页面布局**方面存在的不合理之处，并给出分阶段重构建议，供后续 UI/UX 迭代参考。

---

## 一、现状导航与页面清单

当前侧边栏（`web/src/stores/ui.js`）采用 9 项平铺导航，未区分「当前房间」与「全局管理」作用域：

| 导航项 | 视图文件 | 实际作用域 | 主要承载内容 |
|---|---|---|---|
| 概览 | `web/src/views/OverviewView.vue` | 当前房间 + 宿主机 | 资源指标卡、分片启停、7 项快捷运维/诊断、在线玩家、实时日志与控制台 |
| 房间 | `web/src/views/RoomsView.vue` | 全局 | 房间卡片列表、新建/编辑房间、上传存档、配置方案、管理员名单、黑白名单 |
| 世界配置 | `web/src/views/WorldView.vue` | 当前房间（按分片） | 世界规则与世界生成可视化配置、预设与 `override_enabled` |
| 模组 | `web/src/views/ModsView.vue` | 当前房间（按分片）+ 共享下载 | 模组启用/禁用、配置、更新检查、工坊添加、共享下载队列 |
| 玩家日志 | `web/src/views/PlayerLogsView.vue` | 当前房间（按分片） | 聊天/进出/死亡/复活/公告历史查询、复制 ID、封禁、删除面板历史 |
| 备份 | `web/src/views/BackupsView.vue` | 当前房间 + 全局迁移 | 单房间 ZIP 备份与恢复检查、游戏快照回档、**全局完整迁移** |
| 存档 | `web/src/views/SavesView.vue` | 全局磁盘 + 房间地图 | 全磁盘 `Cluster_*` 盘点、孤儿存档删除、**房间存档地图预览** |
| 配置预览 | `web/src/views/ConfigView.vue` | 当前房间 | 只读预览 `cluster.ini` / `server.ini` / `modoverrides.lua` 等配置文件 |
| 设置 | `web/src/views/SettingsView.vue` | 全局 | 5 组 9 项二级设置：自动维护、异地备份、事件通知、访问密码、工坊 API Key、服务器文件与架构、主题、玩家日志自动刷新、运行信息 |

## 二、全局级核心问题

### 1. 全站过度使用「纯图标按钮（`IconAction`）」，可发现性差且图标撞车
- **现状**：`web/src/components/ui/IconAction.vue` 固定渲染为 `size="icon-sm"` 的纯图标按钮，不显示文字标签，功能含义完全依赖悬停 Tooltip。
- **核心痛点**：
  1. **概览页操作区“盲盒化”**：`web/src/views/OverviewView.vue`（L124–L156）的「分片管理」卡片右上角连续摆放 **7 个纯图标按钮**（故障诊断、立即保存、主世界快进一天、全服公告、回档、全部启动/安装并启动、全部停止）。缺乏文字标签、主次层次与分组分隔；首次开服时「安装并启动」（下载约 4.5GB 服务端）的核心 CTA 也仅是一个小下载图标。
  2. **弹窗与表单按钮风格不统一**：部分弹窗底部确认/取消使用纯图标（`RollbackDialog.vue`、`AnnounceDialog.vue`、`SaveUploadPanel.vue`、`RoomEditor.vue`），另一些弹窗则使用带文字的 `<Button>`（`MigrationDialog.vue`、`RoomProfilesDialog.vue`、`BackupInspectionDialog.vue`）。移动端或触屏设备无法通过 hover 查看 Tooltip，操作成本高。
  3. **相同图标承载完全不同的高权重功能**：
     - `refresh`：在 `ModsView.vue`（L510、L516）同一工具栏上同时代表「检查更新」与「刷新本地模组列表」，极易误点；
     - `clock`：在备份页工具栏代表「游戏快照回档」（`BackupsView.vue` L115），在下方备份表格行内又代表「ZIP 备份回滚」（`BackupTable.vue` L40）；
     - `folder`：分别代表「配置方案」（`RoomProfilesDialog.vue`）、「完整迁移」（`MigrationDialog.vue`）、「复制存档根目录」（`SavesView.vue`）、「重新选择文件」（`SaveUploadPanel.vue`）；
     - `activity`：分别代表「故障诊断」（`DiagnosticsDialog.vue`）、「测试已保存的备份目标」（`BackupRemoteSettings.vue`）、「查看更新进度」（`ModsView.vue`）；
     - `pin`：分别代表「地图预览」（`SavedMapDialog.vue`）与「传送玩家」（`PlayersPanel.vue`）。

### 2. 侧边栏平铺无分组，「房间级」与「全局级」作用域混杂
- **现状**：`App.vue`（L45–L46）在实现层已明确将 `rooms`、`saves`、`settings` 划为全局管理页，其余 6 页为当前房间业务页；但界面上侧边栏 9 项完全平铺（`AppSidebar.vue` L53–L66），且顶栏房间下拉选择器（`TopBar.vue` L68–L82）在所有页面常驻。
- **问题表现**：
  - 在「设置（自动维护 / 异地备份 / 通知）」或「存档」等全局页切换顶栏房间，页面内容毫无变化，容易让用户误以为自动维护或异地备份是按当前选中房间生效的。
  - 顶栏房间选择器下拉项仅显示房间名称，不展示运行状态指示灯；已存在的 `CurrentRoomBanner.vue` 全站未被引用。

## 三、功能入口归属不合理与隐藏过深

### 1. 服务端首次安装进度与更新入口脱离「概览」主流程
- **现状**：`web/src/components/overview/InstallPanel.vue` 虽位于 `components/overview/` 目录且文案包含“安装成功后自动开服，请保持此页面打开”，但目前只挂载在 `SettingsView.vue`（L173–L176）的「设置 → 服务器 → 文件与架构」中，**概览页并未渲染该面板或任何安装进度条**。
- **问题表现**：首次使用在概览页点击「安装并启动」后，仅按钮变灰且统计副标题变为“正在准备开服…”，用户完全看不到 4.5GB 下载的百分比、当前阶段与失败原因，必须自行翻进设置页。

### 2. 「存档地图预览」挂在「存档」页，作用域错位且难发现
- **现状**：`SavedMapDialog.vue`（L66）作为纯图钉图标按钮放在 `SavesView.vue`（L157）工具栏右上角。
- **问题表现**：
  - 「存档」页列表展示的是全磁盘 `Cluster_*` 目录（含孤儿存档），而地图预览弹窗按「房间 + 分片」选择，既不能查看孤儿存档，也不能在表格行直接点击预览对应存档地图。
  - 玩家查看地图的自然入口应在「概览」或「世界配置 / 房间」页，放在偏运维清理性质的「存档」页可发现性极低。

### 3. 「完整迁移」藏在单房间「备份」页中
- **现状**：`MigrationDialog.vue` 入口放在 `BackupsView.vue`（L114）。
- **问题表现**：「备份」页是单房间维度（随顶栏切换房间刷新列表），而「完整迁移」导出/导入的是**全站全部房间、配置方案与自动维护计划**，且要求停止所有房间。将其置于单房间备份页破坏作用域一致性，并与「房间」页的「上传存档 / 配置方案」割裂。

### 4. 「备份」「存档」「上传存档」「回档」概念重叠、入口分散
- 侧边栏同时存在「备份」与「存档」两个一级菜单，新用户不易区分边界：
  - 单房间 ZIP 备份 + 游戏快照回档 + 全局迁移 → 「备份」；
  - 磁盘目录盘点 + 孤儿清理 + 地图预览 → 「存档」；
  - 上传 ZIP 存档新建或覆盖房间 → 「房间」（`RoomsView.vue` L123、`RoomCard.vue` L91）。
- 「备份」页内「回档（游戏快照）」与「回滚（ZIP 恢复）」术语相近且共用 `clock` 图标，容易误操作。

### 5. 「玩家管理」能力分散三处，且房间编辑页混用两套提交模型
- **入口分散**：
  - 在线玩家管理（踢出、封禁、复活、传送、设为管理员）→ 「概览」右侧卡片（`PlayersPanel.vue`）；
  - 历史记录与封禁 → 一级菜单「玩家日志」（`PlayerLogsView.vue`）；
  - 管理员、黑名单、白名单 → 深藏在「房间 → 点击编辑 → 滚动至表单最底部」（`RoomsView.vue` L108–L109、`RoomEditor.vue` L298）。
- **操作断层与心智冲突**：
  - 在「玩家日志」页封禁某玩家后，若想解封，需跨页进入「房间 → 编辑 → 滚动到底部 → 玩家准入名单」；
  - `RoomEditor.vue` 上半部分（基本信息、分片、高级设置）靠顶部「保存」统一提交，而底部的 `RoomAdmins` 和 `RoomPlayerLists` 每次增删都会**即时调用后端接口生效**，同一编辑页内混杂两种提交逻辑且缺少明显分隔说明。

### 6. 「世界配置」的核心可写项藏在 `info` 信息气泡里
- **现状**：`WorldView.vue`（L508–L555）将 `世界生成预设`、`世界规则预设` 和 `启用本文件（override_enabled）` 开关放进了 `info` 图标触发的「路径与说明」Popover 中。
- **问题表现**：`i` 图标通常代表只读说明，用户很难意识到可修改的预设和启用开关藏在其中；当预设与分片类型不匹配时，页面报错不得不引导用户去「路径与说明」里修改预设（`WorldView.vue` L611）。

### 7. 「配置预览」占独立一级菜单性价比偏低
- **现状**：`ConfigView.vue` 为纯只读配置文件查看器，属于低频排查工具，却占据侧边栏一个主入口，拉长主导航。更适合作为「房间编辑」或「故障诊断 / 高级信息」中的次级入口或抽屉。

### 8. 「设置」页二级导航过碎，且把高频/全局操作埋得过深
- **现状**：`SettingsView.vue`（L28–L38）划分为 5 个分组、9 个子页，形成“主侧边栏 + 设置二级侧边栏”的双层嵌套。
- **问题表现**：
  - 多个子页仅含 1 个控件：
    - 「界面 → 玩家日志」仅有 1 个「自动刷新」开关（L199–L208），本应直接置于「玩家日志」页工具栏以便随手切换；
    - 「界面 → 主题」与顶栏主题切换按钮完全重复；
    - 「安全 → 访问密码」和「创意工坊 → API Key」各自仅有一个简短表单。
  - **「退出登录」**藏在「设置 → 安全 → 访问密码」卡片右上角的小图标里（L117），顶栏和侧边栏底部均无登出入口。
  - **「异地备份」**位于设置页，与「备份」页之间缺少直达跳转链接。

## 四、页面布局与交互一致性问题

### 1. 概览页（`OverviewView.vue`）
- **指标卡层次与重点问题**：顶部 4 张指标卡将「当前房间指标（运行分片、进程资源）」与「宿主机指标（宿主机内存、存档盘）」无分隔混排；对极易 OOM 的 DST 服务器而言，「进程资源占用」把 CPU% 作为主数值展示，内存反而缩在灰色副标题里（`OverviewView.vue` L113–L118）。
- **双列空间浪费**：`.overview-workspace`（`components.css` L21–L26）采用固定 50% / 50% 等高两列。当房间未运行或无在线玩家时，右侧「在线玩家」卡片仅显示一行灰字却占据半行宽度与整列高度，挤压下方实时日志区域（`.console` 高度受限于 `clamp(16rem, 36vh, 24rem)`）。
- **缺少关键前置状态横幅**：当前房间缺少 Klei 令牌（`room.needToken`，目前仅在房间卡片上显示小标签）或服务端未安装/安装中时，概览页缺少显眼顶部引导条。

### 2. 分片切换交互不统一，且窄屏隐藏主维度
- `WorldView.vue`（L502–L506）使用横向 Tab 切换分片（仅启用分片），而 `ModsView.vue`（L482–L491）和 `PlayerLogsView.vue`（L287–L294）使用 Select 下拉框（包含停用分片）。
- 当工具栏宽度 `< 720px` 时，`UiToolbarFilters.vue`（L16）会把**分片选择器**连同普通筛选条件一起收进滑块图标弹窗；分片属于主数据源切换维度而非筛选条件，隐藏后用户无法直接感知当前正在查看或修改哪个世界。

### 3. 玩家日志表格过宽导致常规桌面端强制横滚
- `PlayerLogsView.vue`（L351）固定 10 列并设置了 `min-w-[1240px]`。展开侧边栏（220px）后，在常见 1366px / 1440px 屏幕上都会出现横向滚动条，把最核心的「内容」和「封禁」操作列挤出可视区。
- 实际上可将「角色头像 + 玩家名 + Klei ID」合并为玩家身份列（类似 `PlayerIdentity.vue`），将「Steam ID + IP」合并或次要化展示，大幅缩减横向宽度。

### 4. 表格分页样式不统一
- `PlayerLogsView.vue`（L449–L476）采用吸底固定分页条且支持选择每页条数；`SavesView.vue`（L223–L227）与 `BackupTable.vue`（L104–L108）采用随内容区滚动的简化分页，无每页条数选项。

### 5. 跨页引导缺少快捷跳转 & 部分文案过期
- 全站空态与冻结提示均为纯文本（如“请先在「房间」页新建一个房间”“建议先到备份页保留一份整房间备份”），不支持点击直达目标页面。
- 存在旧称/过期文案：
  - `WorldView.vue`（L607）：仍写作 `请先在「总览」关闭服务器再修改`（导航名称已为「概览」）；
  - `SaveUploadPanel.vue`（L219）：仍提示 `需到「模组」页点「更新模组」`（模组页当前已无同名按钮）。

## 五、分阶段优化建议

### 阶段 1：按钮可读性与高危入口分层（已完成）
- 制定按钮规范：
  - **带文字按钮（图标 + 短文案）**：用于页面/卡片主操作、弹窗底部确认/取消、高风险或低频概念入口（安装并启动、全部启动/停止、故障诊断、完整迁移、地图预览、配置方案、立即备份、立即保存等）；
  - **纯图标按钮**：仅保留在表格行内或重复列表项的高频通用动作（复制、刷新、删除、编辑、展开配置）。
- 拆分概览页「分片管理」右上角 7 个按钮为三组：「全部启动/停止（主操作）」+「快捷运维（保存/公告/快进/回档，可分组或收进菜单）」+「故障诊断」。
- 消除同页同图标冲突（如模组页「检查更新」与「刷新列表」、备份页「快照回档」与「ZIP 回滚」）。

### 阶段 2：重构导航分组与统一作用域（已完成）
- 将侧边栏明确拆为两组（8 项）：
  - **当前房间**：概览、世界配置、模组、玩家管理（整合「玩家日志」+「管理员与准入名单」Tab）、备份与回档；
  - **全局管理**：房间管理（聚合新建、上传存档、配置方案、完整迁移）、磁盘存档、系统设置。
- 全局管理页隐藏顶栏房间切换器并展示「全局」作用域标识；房间作用域页顶栏房间选择器增加运行状态点；将「配置预览」下沉为房间编辑与故障诊断弹窗的次级弹窗入口。
- 在顶栏右侧提供显式「退出登录」入口（启用密码时显示）。

### 阶段 3：归位错位入口与优化页面布局
- **概览页**：
  - 未安装/安装中/安装失败时，在概览页顶部直接展示安装进度与操作横幅（复用 `InstallPanel` 核心状态）；缺令牌时显示一键跳转房间编辑的提醒条；
  - 区分房间指标与宿主机指标，突出进程内存占用；将「分片管理 / 在线玩家」由 5:5 调整为更紧凑的布局，释放实时日志高度；增加「地图预览」入口。
- **世界配置页**：将「世界生成预设」「世界规则预设」「启用本文件」从 `info` 气泡移出为可见配置栏，并修正「总览」等过期文案。
- **模组页 / 玩家日志页**：将分片切换器移出 `UiToolbarFilters`，保证窄屏下始终可见；把「玩家日志自动刷新」开关迁回「玩家日志」工具栏；精简玩家日志列宽，避免 1440px 下横向滚动。
- **设置页**：将 9 个碎片化子页合并为 4 个均衡分组（自动维护与异地备份、事件通知、服务器与创意工坊、安全与关于），并在「备份」页增加直达「异地备份设置」的快捷入口。
- **跨页引导**：将关键提示（新建房间、停服、前往备份、前往下载缺失模组等）补齐可点击跳转按钮。
